## [v3.20.2] - 2026-11-25

### Enhancements

- The standalone server is published as a public container image, ghcr.io/scalar-labs/scalardb-postgres-frontend, for linux/amd64 and linux/arm64: one signed tag per release with an SBOM and provenance, and a -SNAPSHOT tag that follows each version line.
- `MERGE` is supported, in PostgreSQL 15's and 17's forms: `WHEN MATCHED [AND ...] THEN UPDATE`, `DELETE` or `DO NOTHING`; `WHEN NOT MATCHED [BY TARGET] [AND ...] THEN INSERT` or `DO NOTHING`; `WHEN NOT MATCHED BY SOURCE [AND ...] THEN UPDATE`, `DELETE` or `DO NOTHING`; and `RETURNING`, with `merge_action()` and the source's and target's columns. The source can be a table, a subquery, `VALUES` or a `WITH` query, with parameters. A row changed twice (`21000`), a duplicate key (`23505`) and a NULL key (`23502`) fail with PostgreSQL's errors.

### Bug fixes

- The server now turns on TCP keepalive for client connections, as PostgreSQL does. A client whose host went down or whose network was cut no longer leaves its session, and any transaction that session holds, open indefinitely: the operating system closes the connection once keepalive probes go unanswered (after about two hours with the default system settings).
- `SELECT "S".*` and `SELECT *` over a table whose alias is quoted and not all lower case, such as `FROM emp AS "S"`, no longer fail with "Unknown column": the columns kept the alias as written.
- A `RETURNING` list that repeats a name, such as `UPDATE t SET v = 2 RETURNING v AS x, id AS x`, returns each column's own value; the last one used to fill every column of that name.
- Built on ScalarDB 3.20.2. The container image ships the ScalarDB Cluster client SDK 3.20.0.
