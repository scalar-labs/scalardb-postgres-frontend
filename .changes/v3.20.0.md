## [v3.20.0] - 2026-10-29

### Enhancements

- First release of the ScalarDB PostgreSQL frontend, a PostgreSQL-compatible SQL interface for ScalarDB. PostgreSQL clients and tools, such as psql, the PostgreSQL JDBC driver and ORMs, connect over the PostgreSQL wire protocol, and their SQL runs on the databases ScalarDB manages, as ScalarDB transactions: each statement outside `BEGIN` is one transaction, and `BEGIN ... COMMIT` is one transaction. It runs inside ScalarDB Cluster nodes (the recommended deployment) or as a standalone server on ScalarDB core. The engine is published to Maven Central as `com.scalar-labs:scalardb-postgres-frontend-engine`, which ScalarDB Cluster embeds. See `docs/user/README.md`, and `LIMITATIONS.md` for what the frontend refuses or does differently from PostgreSQL.
- SQL as PostgreSQL 16 answers it: queries with joins, subqueries, aggregates, window functions, set operations and CTEs; `INSERT`, `UPDATE`, `DELETE` and `INSERT ... ON CONFLICT` with `RETURNING`, also inside `WITH`; and table, index and schema DDL. Each query runs as far as possible in ScalarDB, and `EXPLAIN` shows how. See `docs/user/sql-reference.md`.
- Declared types keep PostgreSQL's rules: `NUMERIC(p,s)` is exact, `VARCHAR(n)`, `CHAR(n)` and `SMALLINT` are checked and shown as declared, and `json` and `jsonb` keep their type. The declarations are recorded in the frontend's metadata table, which `CREATE FRONTEND METADATA TABLES` creates once (see `docs/type-encoding.md`).
- Transactions run at the isolation level the ScalarDB deployment is set to, which `SHOW transaction_isolation` reports as PostgreSQL's closest level; a request for a stronger level fails rather than being ignored. See `docs/user/transactions.md`.
- `pg_catalog` and `information_schema` answer as PostgreSQL 16 does, or fail, so psql, pgjdbc, SQLAlchemy, Sequelize, Prisma and DBeaver read the schema. See `docs/user/clients.md` for the tested clients.
- Under ScalarDB Cluster: a password or an OIDC access token per connection, TLS, Cluster's users and privileges, encryption, and ABAC. See `docs/user/security.md`.
