What PostgreSQL does, where the plan had to guess:
- 21000 "MERGE command cannot affect row a second time" only when a second source row would UPDATE
  or DELETE a target row already changed by the statement. Two matches that both DO NOTHING are not
  an error (merge_twice_matched_do_nothing, MERGE 0), nor is UPDATE then DO NOTHING
  (merge_twice_matched_update_then_nothing, MERGE 1).
- The command tag counts rows inserted, updated or deleted; DO NOTHING rows are not counted
  (merge_do_nothing: MERGE 2 with two matched rows skipped).
- Two inserts of one new key, an insert of an existing key, and an UPDATE moving a key onto another
  row: 23505 on mt_pkey. A NULL key, inserted, assigned or from INSERT DEFAULT VALUES: 23502.
- A source row whose join key is NULL is NOT MATCHED (merge_null_join_key_skipped).
- Parse-time errors: a target column in INSERT's VALUES is 42P01 ("invalid reference to
  FROM-clause entry"), SET t.v is 42703, an unqualified column both sides have is 42702, too few
  INSERT values 42601, an unknown target 42P01, an unknown SET column 42703, SET v = 'x' 22P02.
- Untyped parameters take the types of what they meet: in merge_bind_untyped, $1 compared with an
  int column and inserted into one is int, $2 assigned to a text column is text.
- PostgreSQL 17 forms (Phase 2): NOT MATCHED BY SOURCE / BY TARGET and RETURNING merge_action() run
  natively (MERGE 7; four RETURNING rows with UPDATE, DELETE, INSERT, INSERT).
